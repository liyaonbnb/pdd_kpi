# 旧版数据迁移边界

旧版线上数据继续保留，V2 采用“先复制、后校验、再切换”的迁移方式，不直接改写旧版 Parquet/JSON 文件。

## 可直接迁移

- 订单与推广明细：保留原订单号、平台、店铺、支付时间、商品/规格编码和原始金额。
- 现有商品成本：迁移为单品成本版本；店铺级商家编码映射先进入待确认映射表。
- 组合商品：已有明确商品编码/规格编码的记录进入链接映射；无法唯一匹配的进入人工确认队列。
- 店铺与仓库：上线前为每个店铺指定一个生效区间内的共享仓库，默认不跨仓扣减。

## 无法从旧数据可靠推导

- 历史真实批次、批次成本和历史入库时间。
- 历史订单发生时的真实加权平均成本（旧版只有当前成本配置）。
- 旧订单的 BOM 版本。

这些记录不伪造历史事实：按用户确认的库存启用日，为每个“仓库 + 单品”建立一个 `LEGACY-OPENING` 虚拟期初批次；旧订单的历史成本保留旧版结果，启用日之后的新订单才使用 V2 快照。

## 切换步骤

1. 管理员在 V2 设置库存启用日（例如 `2026-09-15`，实际日期由上线后选择），并录入昆山仓、辉煌仓、外高桥仓期初批次。
2. 导入旧订单到 V2 经营数据表，标记 `inventory_status = legacy`，不触发库存扣减。
3. 对商品、组合、链接映射执行未匹配检查；未匹配项不得静默扣库。
4. 从启用日开始，按支付时间升序重放订单库存动作；库存不足的订单进入异常队列，但经营数据照常入库。
5. 抽样核对库存余额、成本余额、订单成本快照和日报 KPI，确认无误后锁定启用日。

## 回滚策略

- 迁移阶段使用独立数据库 schema 或独立数据库，不改旧版数据目录。
- V2 导入批次、库存交易和快照均有幂等键，可以按批次作废后重放。
- 启用日锁定后不允许直接修改；如需调整，新增一条调整交易并保留审计记录。
